## Valid Parentheses

https://leetcode.com/problems/valid-parentheses/

Accepted, 103/103, 1 ms, 19.31 MB - https://leetcode.com/problems/valid-parentheses/submissions/2179378263/

```python
class Solution:
    def isValid(self, s: str) -> bool:
        stack = []
        pairs = {')': '(', ']': '[', '}': '{'}
        for c in s:
            if c in pairs:
                if not stack or stack[-1] != pairs[c]:
                    return False
                stack.pop()
            else:
                stack.append(c)
        return len(stack) == 0
```

Один проход, O(n). Открывающая - push, закрывающая - сравниваем с вершиной и pop, в конце стек пустой.
Стек потому что закрывающая скобка всегда относится к последней открытой, т.е. LIFO.

`"()" -> true, "()[]{}" -> true, "(]" -> false, "([])" -> true, "([)]" -> false`

## Group Anagrams

https://leetcode.com/problems/group-anagrams/

Accepted, 129/129, 17 ms, 23.95 MB - https://leetcode.com/problems/group-anagrams/submissions/2179378728/

```python
from collections import defaultdict
from typing import List

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        d = defaultdict(list)
        for w in strs:
            cnt = [0] * 26
            for c in w:
                cnt[ord(c) - ord('a')] += 1
            d[tuple(cnt)].append(w)
        return list(d.values())
```

Словарь, ключ - частоты букв (кортеж из 26 чисел), у анаграмм он одинаковый. O(n*k).
Можно было бы ключ `sorted(w)`, но это O(n*k*log k).

`["eat","tea","tan","ate","nat","bat"] -> [["bat"],["nat","tan"],["ate","eat","tea"]]`

**Ответ агента:**

> **Valid Parentheses.**
> Выберу стек, потому что задача по сути про вложенность: последняя открытая скобка должна закрыться первой, а это ровно LIFO-дисциплина. Иду по строке: открывающую кладу на стек, для закрывающей снимаю вершину и проверяю, что типы совпадают (удобно держать маленькую хеш-таблицу соответствий закрывающая -> открывающая); если стек пуст или тип не тот, сразу false. В конце строка валидна, только если стек опустел. Время O(n), так как каждый символ обрабатывается один раз, а push/pop за O(1). Память O(n) в худшем случае (строка из одних открывающих скобок). Полезная ранняя проверка: нечётная длина -> сразу false.
>
> **Group Anagrams.**
> Хеш-таблица «канонический ключ -> список строк»: анаграммы — это строки с одинаковым мультимножеством букв, поэтому достаточно придумать ключ, инвариантный к перестановке. Вариант 1: отсортированная строка (например, "eat" -> "aet"). Время O(n * k log k), где n до 10^4 строк, k до 100 символов; память O(n * k) под ключи и группы. Вариант 2 (лучше по асимптотике): счётчик из 26 частот, превращённый в кортеж или строку вида "1#0#0#...": ключ строится за O(k), итого O(n * k). На практике при k <= 100 сортировка часто не медленнее, потому что константа у счётчика (26 элементов на каждую строку, включая короткие) заметна, но формально второй вариант строго лучше и его стоит назвать на собеседовании. Альтернатива с произведением простых чисел (каждой букве — простое, ключ — произведение) красива, но переполняется для длинных строк, поэтому я бы её только упомянул. Наивный подход «попарно сравнивать» — O(n^2 * k) и не подходит.
